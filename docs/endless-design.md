# 无尽与挑战系统：计划（0.2.2 只写计划，不实现）

> 状态：**仅计划**。0.2.2 没有为它写任何代码、界面、截图或测试。本文件说明下一轮要做什么、怎么做、怎么验收。

## 目标

通关之后，游戏仍然有东西可以追求：同一段代码可以越写越快、越写越短。这种进步要能用确定的数字衡量，并且能跟一份公开的基准比。

- 不靠数值膨胀、也不靠无限加成撑时长。玩家的进步来自代码本身。
- 成绩完全由模拟器决定：同一段代码、同一个挑战，在任何机器上跑出的分数都一样。
- 每个挑战都附带一份基准解，就是对应技能的范本。玩家可以跟它比，也可以跟自己的历史最好成绩比。

## 1. 标准化挑战

挑战是一份固定的题面，写在 `game/challenges/<id>.json`，由模拟器读取。题面包含：

| 字段 | 含义 |
| --- | --- |
| `id`、`title`、`story` | 编号、标题、一句话背景 |
| `requires` | 需要已解锁的技能；未解锁时挑战锁住，提示去买哪项 |
| `world` | 田边长、初始地块与作物、初始背包 |
| `seed` | 固定随机种子（与 `simulate()` 同一套机制） |
| `goal` | 结束条件，例如「累计 1000 干草」「收一次 ≥6×6 南瓜」「走出 5 个迷宫」「仙人掌整片排好收一次」 |
| `limit_ticks` | 超时判负的上限，防止死循环 |
| `baseline` | 基准解文件，默认是对应技能的范本 `game/exemplars/<id>.cpp` |

第一批挑战按主线取材，每个作物或机制一题，例如：

- 草原 1000（干草）
- 灌木林（木头）
- 胡萝卜轮作
- 最大的向日葵
- 6×6 南瓜
- 五个迷宫
- 整片仙人掌
- 恐龙 50 节
- 双机农场

难度递增的变体（田更大、目标更高）放在同一题下，叫第 2、3 档。

## 2. 确定的评分

挑战在模拟器里无头运行，界面只负责回放。每次提交记录三项成绩：

1. **tick**：达成目标用的游戏 tick 数。这是主成绩，越少越好。
2. **代码量**：去掉注释和空白后的词法单元（token）数，越少越好。按 token 计，所以改缩进、改变量名长短都不影响成绩。
3. **动作数**：调用农场动作（move、harvest、plant、till、use_item 等）的次数，越少越好。查询不计入。

### 确定性的保证

- 固定 `seed`。
- 每次都从题面重新建世界。
- 无人机按固定顺序调度。
- 禁止 `get_time()` 影响结果：挑战模式下它返回 tick 换算的秒数，不读真实时钟。
- 同一份代码运行两次，三项成绩必须逐位相同。单元测试会用每题的基准解跑两遍来对拍。

### 成绩的保存

成绩写在存档里，按 `challenge_id + 档位` 保存：

- 最好的 tick
- 最少的 token
- 最少的动作
- 达成每项最好成绩时的代码快照

## 3. 个人最好成绩与基准对比

- 结果面板列出三项成绩，每项都和两样东西比：
  - 「范本基准」：把对应技能的范本放到这道题上跑出的成绩，由构建时生成，不随存档改变。
  - 「个人最好」。
- 显示为差值和比例，例如 `tick 18 400（范本 24 000，快 23%）`。
- 三项各自独立。快但长的解、短但慢的解都能各自刷新纪录，不强迫玩家只走一条路。
- 每项成绩只要胜过范本，就点亮一枚小徽章。徽章只表示「做到过」，不给任何加成。
- 结果面板上有「对比范本」按钮，把范本和玩家代码左右并排，用代码区同款高亮显示。

## 4. 持续成长的节点

主线技能买完以后，技能树末端再接一组「无尽」节点。它们不提供新语法，而是推动玩家优化代码：

- **挑战入口节点**：主线全通后解锁，打开挑战列表。
- **档位节点**：在某题第 1 档胜过范本 tick 后，开放第 2 档；以此类推，最多 3 档。
- **限制节点**：可选的附加规则，用于练某种写法，例如「只允许一架无人机」「不准用数组」「代码 ≤ 120 token」。达成后记一枚徽章。
- **周常节点**：每周用新的种子和田块生成一题。种子由 ISO 年周计算，不联网，所有人的题面一样，便于比较。

成长全部来自玩家自己的代码和成绩，不加数值。主线经济在通关后照常运转，不需要再平衡。

## 5. 与范本的关系

- 每道挑战的基准解直接引用 `game/exemplars/` 里的范本，所以「范本」既是教学示例，也是可以被超越的及格线。
- 范本递进的原则（见 `docs/playthrough.md`）不变：基准用的是朴素正确的写法，留出优化空间。
- 挑战不另写更强的「官方最优解」，以免剧透。

## 6. 实现顺序（下一轮）

1. **模拟器。**
   - 解析挑战文件，实现目标判定、`limit_ticks` 和三项计分。
   - token 计数复用解释器的词法分析。
   - 写单元测试：每题的基准解能完成，两次运行成绩逐位相同。
2. **存档。** 按挑战和档位保存最好成绩与代码快照，并兼容旧存档。
3. **界面。**
   - 挑战列表。
   - 结果面板，展示三项成绩、差值和徽章。
   - 「对比范本」并排视图。
   - 回放复用现有 3D 场景。
4. **节点。** 在技能树末端接入挑战入口、档位、限制和周常节点。
5. **验收。**
   - 冒烟测试打开挑战，跑基准解，检查成绩面板。
   - 通关测试末尾跑一遍第 1 档。
   - 截图。

## 不做的事

- 不做联网排行榜和账号。
- 不把真实时间计入成绩。
- 不让挑战成绩反过来加速主线。
